# 关键选型

本文给架构师和技术主管做否决：每一项都是「要解决的问题、放弃了什么、选定了什么、二开必须怎样」。Formily 只是其中一项。清单先看，细节按锚点下钻。

动手写插件前，把「二开时不要」落到 [二开红线](./constraints.md)。

## 先看结论

| 决策 | 选定 | 二开时不要 |
|------|------|------------|
| 扩展方式 | 微内核 + 五类插件 | 把行业图表和版式写进内核 |
| 分析入口 | 数据集与语义模型 | 图表直连业务库或自带 SQL 编辑器 |
| 运行时查询 | 宿主 `POST semantic/query` | 插件自己发查询 |
| 图表属性 | Formily JSX Schema | 每个插件一套手写表单状态；也不要换成未接入的 JSON 文件 |
| 连接表单 | Ant Design Form | 把账号密码表单套进 Formily |
| 筛选 | 运行时状态 `actionValues` | 图表互相抛事件 |
| 跳转 | 交互规则 `openDashboard` / `openUrl` | 做成 Action 插件 |
| 划过 | 可撤销强调 | 用 hover 筛数或跳转 |
| 版式 | 仪表盘管整页，布局管页内 | 一种插件兼管两套坐标系 |
| 自由大屏 | 固定逻辑尺寸 + 等比缩放 | 高度随内容撑高 |
| 装饰点击 | 默认穿透 | 装饰层全局可点 |
| 语言 | 全栈 TypeScript | 用 Java / Python / Go 写业务插件 |
| 前端状态 | React + Zustand | Vuex、全局事件总线 |
| 插件加载 | 内置插件静态打包 | SystemJS 远程脚本拼页面 |
| 图表库 | 插件内选择；内置是 G2 / S2 | 在内核锁死唯一引擎，或假设已经接了 ECharts |
| 构建 | Rsbuild | 为了快而换成开发/生产行为不一致的方案 |
| HTTP 服务 | NestJS + Fastify | Express |
| 权限 | 身份与 Casbin 资源权限分离 | 把 ACL 塞进登录令牌或插件 |
| 数据存放 | 元数据在 PostgreSQL，业务数据留在客户库 | 把客户业务库搬进平台库才能画图 |
| AI | 生成平台原生配置 | 另做一套 AI 报表运行时 |
| 配色 | 品牌色只约束产品外壳 | 把用户大屏改成工业蓝 |
| 无障碍 | 不做读屏合规 | 为插件补 WCAG |
| 官方 Demo | 同一套数据 + 目录文案 overlay | 按语言复制空间或翻译图表内容 |

---

## 微内核，行业差异不进内核

**问题。** 行业图表、地图、装饰和大屏版式会不断加。写进内核后，每次定制都要改编辑器、发一版平台。

**放弃。** 把「平台支持的图表」做成一张写死的枚举，由核心团队逐个合并。

**选定。** 宿主提供壳、查询、权限和状态。图表、数据源、交互、仪表盘、布局是插件。内置插件与二开插件走同一套模块形状：`meta` + `Panel` + `Config`。

**二开。** 新场景新建插件目录并登记，不改查询控制器和权限模块。插件之间不互相 import 业务实现。

## 数据集是唯一分析入口

**问题。** 若每个图表自己写 SQL、自己选库，口径无法复用，权限和审计也落不到同一张资产上。

**放弃。** Grafana 式「图表自带 QueryEditor、直连数据源」。历史方案里图表调用 `datasource.query()` 已废弃。

**选定。** 数据源插件只保存连接。数据集（以及已发布的语义模型）是图表、仪表盘和问数的入口。联表在治理层按已登记的数据集编译，用户不向平台提交任意 SQL。

**二开。** 新图表声明自己需要的维度/度量形态，不声明自己连哪台库。新数据源做完后，用户仍要建数据集才能配图。

## 运行时查询在宿主，不在插件

**问题。** 筛选、下钻、联动会改变查询条件。若每个插件自己请求，条件会不一致，也会绕过权限。

**放弃。** 插件内 `fetch` 业务库；也放弃让新图表去调旧的 `POST query/panel`。该接口仍在 DataTalk `QueryService` 上，**当前图表宿主不走它**。

**选定。** `usePanelQueryController` 用 `FilterEngine` 算出附加条件，再 `POST semantic/query`。插件 `Panel` 只接收 `data`、`config`、`loading`。可选的 `mapData` 只做结果映射，不做取数。

**二开。** 渲染函数可以替换，取数函数不能替换。半依赖查询的文本组件（如富文本里的指标胶囊）仍由宿主供数，不自己打接口。

## 图表属性用 Formily，而且是 JSX Schema

**问题。** 图表属性又多又会联动：图例、轴、标签、条件显隐、异步校验。每个插件用 `useState` 手写，改一个字段容易整表重绘，AI 也无法按稳定结构改配置。

**放弃。**

- 每个图表一套不受控的 React 表单。
- 把 Formily 的可视化设计器 Designable 当成产品能力。平台没有交付它。
- 把属性当成运行时 JSON 文件加载。个别目录里有 `baseConfig.json`，源码并未引用。

**选定。** `@formily/core` + `@formily/react`，组件来自 `@luminaryworks/formily-antd-v6`。`BaseConfigForm` 创建表单，`onFormValuesChange` 把值交给宿主；字段用 `SchemaField` 的 JSX 描述。这三件事是选它的原因，而不是「表单库里比较有名」：

- **Schema 驱动。** 结构、校验和联动写在 Schema 上，配置可以序列化进 `panel.config`。人和 AI 改的是同一份描述。
- **联动独立于界面。** 表单内部是 observable。副作用放在 effects 里，字段依赖不必散落在各个输入框的 `onChange`。
- **字段级更新。** 状态按字段拆开，大型属性面板不必整棵表单重绘。

宿主写回 `panel.config`（图表编辑器或大屏侧栏）。不要把每一次实时 config 再回喂给 `BaseConfigForm` 当新的 `initialValues`，否则表单会被拆掉重建。

**二开。** 新图表的 `Config` 包一层 `BaseConfigForm`，里面继续写 `SchemaField.*`。需要新控件时注册进 `SchemaField` 的 components，而不是在 Schema 外面另起一套状态。

## 数据源连接表单不用 Formily

**问题。** 连接配置是短表单：主机、端口、库、账号、密码、测试连通。它要提交给后端并处理测试状态，不需要图表那种深层联动。

**放弃。** 为了「所有插件属性都 Formily」把连接表单也套进 Schema。两种表单的生命周期不同，硬统一会把测试连接和密钥处理搞乱。

**选定。** 数据源 `Config` 使用 Ant Design `Form`。连通测试由宿主注入 `test()`，插件只调用它（见 `useConnect`）。保存走 `POST datasource` / `PATCH datasource/:mark`。

**二开。** 新数据源复制 MySQL 的 Ant Design 表单结构。不要把图表的 `BaseConfigForm` 搬到数据源插件里。

## 筛选是状态，不是事件网

**问题。** 一张仪表盘上许多图要共享时间、单选和下拉。若图和控件互相监听，增加一个图就要改旧图，条件也会重复请求。

**放弃。** 全局大 `filters` 广播；图表之间 `emit` / `on`；在插件里直接改别的图的 query。

**选定。** 交互插件把当前值写入 `useDashboardRuntimeStore` 的 `actionValues[flag]`。`FilterEngine.computeForPanel` 为每个图表派生 `extraWheres`。条件没变的图不重查。目标若是交互控件自身，不产生过滤。

**二开。** 新筛选控件必须有稳定的 `flag`，用 `setActionValue` 写入。不要 import 某个图表的模块去通知它刷新。

## 跳转不是一种交互插件

**问题。** 「筛选」和「离开当前页」看起来都是点击，但生命周期完全不同。筛选可撤销、可分享进仪表盘状态；跳转是导航。

**放弃。** 做一个「打开链接」Action，或在图表插件里 `window.open`。

**选定。** `openDashboard`、`openUrl`、`openDetail` 是版本级 `interactions` 的效果，由 `effectHandlers` 执行。插件只上报事件。`setVariable` 仍是交互效果，虽然它会写 `actionValues`，但不是一个 Action 插件。

**二开。** 大屏菜单、热点、图表点击若要跳转，声明能发出的事件（如 `menuItem`），把目标配在交互规则里。见 [仪表盘交互能力](/product/dashboard-interactions)。

## 划过不写查询

**问题。** 鼠标划过会高频触发。拿它筛数，查询和画面都会抖；拿它跳转，用户无法稳定完成操作。

**放弃。** hover 写入 `extraWheres`、hover 打开链接。校验会拒绝 hover 加 `openUrl` / `openDashboard` / `openDetail`。

**选定。** 划过只做可撤销效果（强调、显隐）。离开即恢复。真正改数据或改页面的操作使用点击、联动或交互规则。

**二开。** 不要在插件的 `onMouseEnter` 里请求数据或改筛选。数据点点击走宿主注入的 `onPlotClick`。

## 整页几何和页内容器分开

**问题。** 门户要滚动网格，指挥中心要固定大屏，手机要单列。页内还要分组、标签和轮播。合成一种「布局插件」后，坐标系会打架。

**放弃。** 一种 dashboard 插件同时描述整页和页内嵌套；历史的 card-panel / tmagic 叫法。

**选定。**

| 注册表分类 | `mode` | 内置 kind | 职责 |
|------------|--------|-----------|------|
| `dashboard` | `dashboard` | `grid` / `position` / `list` | 整页几何 |
| `layout` | `layout` | `row` / `tab` / `swiper`（另有占位 `placeholder`） | 页内容器 |

嵌套槽位里的画布必须与宿主 `dashboardKind` 相同。深度编辑走 Focus Mode：独立的本地版本，保存合并，取消丢弃。`openDetail` 不复用 Focus Mode。

**二开。** 新的整页坐标系做仪表盘插件；新的页内分组做布局插件。不要在布局插件里改整页缩放规则。

## 自由布局不随内容长高

**问题。** 展厅和大屏要在不同分辨率上保持构图。高度随内容变化后，设计稿无法对齐，拼接屏也无法等比缩放。

**放弃。** `position` 使用「固定宽度、高度 auto」。流式增高不是自由布局的模式。

**选定。** 固定逻辑尺寸（默认 1920×1080，可 2K / 4K）加绝对定位，再整体等比缩放。需要纵向滚动的分析使用 `grid`。`list` 才是单列流式。

**二开。** 不要在自由布局插件里按子元素测量高度并撑开画布。见 [自由布局固定尺寸](/product/position-layout-fixed-canvas)。

## 装饰默认点不中

**问题。** 大屏有标题、边框、动效。若它们都接收点击，会挡住后面真正的图表和筛选。

**放弃。** 装饰层全局 `pointer-events: auto`。

**选定。** 运行态装饰默认穿透。只有配了交互规则，或 `capabilities.emitsInteraction` 声明了可点击热点的插件才接收指针事件。

**二开。** 新装饰默认不可点。菜单、按钮类装饰要显式声明能发出的事件，并仍把跳转交给交互规则。

## 全栈 TypeScript

**问题。** 插件、查询 DTO、语义字段和嵌入令牌若分属多种语言，二开要维护两套模型，AI 也更容易改错一层。

**放弃。** 用 Python、Java 或 Go 作为业务主语言。热点可以下沉 Rust / WASM，但不因此把仓库改成多语言业务栈。

**选定。** DataView 与 DataTalk，以及插件契约，都是 TypeScript。Node ≥ 24。禁止 `any`。

**二开。** 插件用 TypeScript 编写，和编辑器同一工具链。不要用其他语言写一个「旁路图表服务」再嵌进仪表盘冒充插件。

## React 与 Zustand

**问题。** 查询、筛选、编辑草稿要能追到单一状态。类组件和跨插件事件会把数据流拆碎。

**放弃。** Vuex（历史文档）；把仪表盘运行时做成窗口级事件总线。

**选定。** 函数组件和 hooks。插件注册表、编辑态、`actionValues` 在 Zustand。React 单向数据流用来保证：改的是状态，渲染是结果。

**二开。** 插件从 store 读它被允许写的那一块（例如交互控件写 `actionValues`），不要把查询结果缓存进插件模块级变量。

## 内置插件静态打包

**问题。** 运行时拉取远程脚本可以「热插拔」，但版本、签名、权限和离线交付都不可控，也和历史 SystemJS 方案一起被放弃。

**放弃。** SystemJS 动态加载作为日常开发路径。非内置的 `fetchPlugin` 只是兜底，不是二开的主路径。

**选定。** 各类 `index` 静态 import 内置插件，写入 `PanelSourceBuildIn`、`DataSourceBuildIn`、`ActionSourceBuildIn`、`DashboardBuildIn`、`LayoutBuildIn`。`getPlugin(kind, category)` 先查内置。

**二开。** 新插件进对应映射，随 DataView 一起构建。见 [注册与加载](./design.md)。

## 图表库不锁在内核里

**问题。** 不同图适合不同引擎：统计图、表、关系图的渲染模型不一样。内核绑定唯一库后，换引擎等于改平台。

**放弃。** 平台 API 暴露某一种图表 option 结构，强制所有插件使用它。也没有把 ECharts 列为已接入依赖。

**选定。** 内核把 `data` 和 `config` 交给插件。内置统计图目前经 `useRenderChart` 使用 AntV G2，表格使用 AntV S2。依赖里没有 `echarts`。替换渲染库是插件内部的事，只要仍消费宿主给的数据。

**二开。** 可以在自己的 `Panel` 里选用合适的渲染库，但不要让配置 Schema 直接等于某个库的 option 全量透传，否则换库和 AI 修改都会绑死。把「查询结果 → 库 option」收进插件内的 hook。

## Rsbuild

**问题。** 可视化编辑器依赖多、插件多。若开发服务器和生产构建行为不一致，插件问题会留到发布才出现。

**放弃。** 只按冷启动速度选构建工具，而不看开发和生产是否同一条管线。

**选定。** Rsbuild。看重与 Webpack 生态的兼容，以及开发/生产一致性。

**二开。** 插件随 DataView 的 Rsbuild 构建，不要另起一个 Vite 子应用当作图表插件。

## 后端是 NestJS + Fastify

**问题。** 查询、连接测试和鉴权是 I/O 密集的 API，不是页面渲染服务器。

**放弃。** Express，以及 Nest 的 Express 适配器。

**选定。** DataTalk 使用 `FastifyAdapter`。新的 HTTP 能力走 Fastify 插件和钩子。

**二开。** 新数据源的连接与查询在 DataTalk 模块里扩展，不另起一个 Express 服务。见 [开发数据源插件](./guide-datasource.md)。

## 身份和资源权限分开

**问题。** 企业 SSO 回答用户是谁。空间、仪表盘、数据源能看什么若写进登录令牌，换一个看板就要重签 token，插件也容易把权限判断写散。

**放弃。** 在 IdP 里维护 BI 资源 ACL；在插件里读取「是不是管理员」决定画不画。

**选定。** 统一账号或企业 SSO 负责身份。DataTalk 用 Casbin 计算资源权限。JWT 不承载细粒度 ACL。

**二开。** 插件不实现鉴权。看不到的资源应由 API 拒绝，而不是靠前端藏按钮。

## 元数据与业务数据分开

**问题。** BI 平台要存仪表盘、数据集和连接配置，但客户的业务数据通常不能搬走。

**选定。** 平台元数据用 TypeORM 存在 PostgreSQL。业务查询经连接器打到客户的 MySQL、PostgreSQL、SQL Server 等。需要加速时由连接侧的分析库承担，托管分析存储默认关闭。

**二开。** 不要把插件运行所需的业务明细写进平台库来「图省事」。连接配置可以入库，明细留在客户数据源，经数据集查询。

## AI 生成的是平台配置

**问题。** 若 AI 另画一套图或另写一份无法编辑的报告，结果不能发布、不能授权、不能改口径。

**放弃。** 聊天窗口里的一次性答案当作正式看板。

**选定。** AI 写入数据集、图表 config、布局等平台原生对象。数字来自语义查询，不来自模型编造。用户可以改、回退、发布。

**二开。** 插件继续消费 `config` 和 `data`。不要为 AI 做一条绕过 Schema 的专用渲染协议。

## 品牌色不约束用户内容

**问题。** 产品外壳需要统一的工业蓝。客户的大屏要服从行业场景：能源、水务、安防的配色各不相同。

**选定。** Logo、官网、控制台和编辑器 chrome 使用品牌色。用户画布、素材库和 Demo 大屏不受此限制。

**二开。** 图表默认色可以为这种图服务，不要强制 `#3A84FF`。不要把品牌规范写进插件校验。

## 不做读屏无障碍

**问题。** 产品是 BI 与数据可视化，不把盲人、弱视用户的读屏合规纳入范围。

**选定。** 不把 WCAG、读屏文案、焦点陷阱列为插件需求。

**二开。** 不要主动加 `aria-*` 或无障碍专页。若合同要求无障碍，先改产品决议，而不是在插件里私自加。

## 官方 Demo 不按语言分叉数据

**问题。** 为每种界面语言复制一套空间或翻译图表里的字段，Demo 与真实产品模型会分叉，二开也无法对照。

**选定。** 同一套 seed。只 overlay 展厅卡片和仪表盘目录上的名称。

**二开。** 不要给图表、字段或轴标签加 `nameEn` 之类的多语言字段。
