# 仪表盘交互能力

> **受众**：产品、售前、实施、配置仪表盘的业务用户  
> **设计与实现**：[仪表盘交互引擎](../develop/dashboard-interact-engine.md)  
> **总览**：[完整产品能力 · 仪表盘与大屏交互](./features.md#仪表盘与大屏交互)

BI 看板不是静态截图。用户改一个下拉、点一张图、点大屏菜单，相关图表要跟着变，同时不能把整页所有图都重查一遍。DataLuminary 把这件事拆成四类配置，共用同一套运行原理。

## 1. 原理：操作写成状态，图表自己算要不要重查

用户每做一次操作，产品只改仪表盘内存里的一小段状态，不让图表互相发消息。

| 用户做了什么 | 写成什么状态 | 谁来响应 |
|--------------|--------------|----------|
| 改筛选控件 | 这个控件的当前值（按组件标识 Flag 存放） | 落在作用范围内的图表，算出新的过滤条件后再查询 |
| 点主图做联动 | 主图这次点中的维度值 | 这条联动里配置的从图表，附加同一套过滤后再查询 |
| 在本图下钻 | 这张图当前下到第几层、点中了什么值 | **只有这张图**换维度再查询；标题面包屑负责返回 |
| 点一下做高亮、切页、开详情、跳转 | 当前观看的表现（高亮、哪一页、浮层） | 改外观或导航，**不**因此重查数据 |

因此：

- 没被这次操作影响到的图保持不动，不会因为旁边点了一下就全部刷新。
- 筛选、联动、下钻改变的是**查询条件**；高亮、显隐、切页改变的是**这一次怎么看**。后者离开页面就消失，也不会写进分享链接。
- 图表插件自己不监听别的图表。配置写在仪表盘上，运行时由平台统一解释。

编辑页顶栏「过滤」里的**全局过滤**不走这套交互。那是打开仪表盘就带上的固定条件，由查询侧强制注入。交互是用户操作之后才叠加的条件，两者可以同时存在。见 [全局过滤](./features.md#仪表盘全局过滤)。

## 2. 为什么拆成四类，而不是一个「点击联动」

四类解决的问题不同。合成一个按钮，配置会互相覆盖，运行时也无法决定「这次点击该下钻还是该跳转」。

| 能力 | 解决的问题 | 配置落在哪 | 不要拿它做 |
|------|------------|------------|------------|
| **筛选控件** | 用户主动选一个值，多张图按同一口径过滤 | 画布上的输入、下拉、单选、时间等控件 | 切大屏页、打开外链 |
| **图表联动** | 点主图的某个维度，一组从图表长期跟着变 | 编辑器顶栏「联动」 | 只让邻卡发光、或打开另一张仪表盘 |
| **图表下钻** | 同一张图从省到市、从年到月往下看 | 这张图的查询配置里打开下钻 | 去改别的图 |
| **交互规则** | 点菜单切页、强调、开详情、跳转、空闲复位 | 面板「交互」Tab，保存在仪表盘版本上 | 代替「联动」做主从维度绑定 |

筛选控件和联动都会改查询。交互规则里也可以「筛选面板」，但那是点一下临时加条件，和「联动」走同一条过滤通道，不是第二套查询引擎。长期的主从关系仍应配在「联动」里，避免同一对图配两遍、点一次触发两次过滤。

状态告警卡片顶部的四级计数是**这张卡片内部**的筛选，不经过联动，也不会去改别的图。见 [状态告警卡片](../plugins/status-alarm-card.md)。

## 3. 配置筛选控件

筛选控件是画布上的一块面板（下拉、输入、单选、多选、时间等），不是图表插件里的一个开关。

1. 在仪表盘编辑器把控件拖进画布。
2. 打开该控件的配置。先写 **组件标识（Flag）**：运行时用这个名字记住当前值。同一张仪表盘里不要重复。
3. 配置 **选项从哪来**（数据集字段、数据字典或手工录入）。这一步只决定下拉里有什么，**不**决定去过滤图表的哪一列。
4. 配置 **作用范围**，可以多行：
   - 选数据集，再选要影响的图表，或选「全部」（该数据集上的图表）。
   - **对应字段**从目标数据集的字段里选，不能手输列名。时间范围控件这里选的是时间字段。
5. 保存控件，再保存仪表盘。

查看时：用户改控件 → 平台记下 Flag 的值 → 只重查作用范围内、且对应字段能对上的图。图片、视频等不查询的面板会被跳过。

打开带 `av` 参数的链接时，可以只读恢复这些 Flag 值（方便把「已选华东」分享出去）。页面打开后不会再把用户的新选择写回地址栏。高亮和当前页签不在这个参数里。

## 4. 配置图表联动

联动表示：点这张主图上的一个维度，一组从图表按约定字段过滤。

1. 仪表盘编辑器顶栏点 **联动**，进入联动列表。
2. 新建一条：指定 **主图**、主图上触发的 **维度**。
3. 为每张从图表指定用哪个字段接收这个值。字段同样从数据集里选，不要手写。
4. 保存联动配置，回到画布后再保存仪表盘。联动和布局、交互规则一起存在这个仪表盘版本上。

查看时点主图的数据点：从图表加上这条过滤并重新查询。再点同一个点，等于取消这次联动，从图表回到未过滤状态。

主图如果还能下钻，**下钻优先**：第一次点击先进入下一层，不会同时去改从图表。需要「点区域既下钻又联动」时，应把联动配置在已经不能再下钻的那一层，或不要在这张主图上开下钻。

## 5. 配置图表下钻

下钻只发生在**同一张图**内部：例如先看省份，点某省后再看该省的城市。

1. 打开这张图的图表编辑器，在查询区找到下钻。
2. 打开下钻，并按从上到下的顺序添加路径上的维度（省 → 市，或年 → 月）。图表类型须支持下钻；指标卡这类没有维度的图不能下钻。
3. 保存图表，再保存仪表盘。

查看时点数据点进入下一层，图标题出现面包屑，点面包屑返回上一层。返回或换层都只重查这一张图。

## 6. 配置交互规则

交互规则回答的是：「点这块（或选这个菜单、空闲一会儿）之后，除了查数以外还要发生什么。」规则挂在仪表盘版本上，不写进某一个图表插件，也不是再拖一个 Action 控件。

### 6.1 入口

1. 在编辑器里选中**触发源**面板：图表、装饰热点，或大屏导航。
2. 打开 **交互** Tab。图表的完整编辑器在右侧；装饰件是精简表单，字段更少。
3. **添加规则**。一条规则先选触发，再 **添加效果**。一条规则可以有多个效果（例如同时强调邻卡并打开详情）。
4. 需要多套行为就再加规则（单击做高亮，双击做跳转）。
5. 关掉面板编辑器，**保存仪表盘**。规则这时才和版本一起落库。删掉面板后，指向它的规则会被裁掉，不会留下指向空面板的配置。

没有效果的规则不要留着：查看时点了不会有可见变化。

画布级的 **无人值守**（空闲多久后复位、是否自动巡航切页）不挂在某一张图上，配在交互策略里。

### 6.2 选触发

| 界面上的触发 | 什么时候发生 | 用来做 |
|--------------|--------------|--------|
| 单击 | 点面板内容区，或已设为可点的装饰 | 高亮、切页、开详情、打开链接 |
| 双击 | 双击同一面板 | 和单击分开的第二套动作；不要和单击配成两套导航 |
| 悬停 | 指针进入，离开后撤销 | 只做短暂强调或显隐 |
| 数据点点击 | 点到图表上的一个柱、点、区域 | 需要带上维度值：筛选其它图、写入变量 |
| 菜单项 | 大屏导航选中某一项，须填该项的 key | 顶栏切页或打开对应链接 |
| 空闲 | 一段时间没有操作（毫秒） | 回到首页或清掉临时状态；间隔不要设得过短 |

悬停**不能**用来筛数或跳转。指针划过大屏时会不断进出面板，用悬停改查询或打开新页面会造成抖动和误跳转。

### 6.3 选效果

| 界面上的效果 | 用户看到 | 会不会重查 |
|--------------|----------|------------|
| 强调面板 | 发光、描边，或压暗其它面板 | 否 |
| 显示 / 隐藏面板 | 目标面板出现或消失 | 否 |
| 激活槽位 | 标签页或轮播切到指定页 | 切到的那一页若从未查过，会按自己的查询去取数；不改其它图的过滤 |
| 筛选面板 | 目标图按这次点中的维度过滤 | 是，且与「联动」共用过滤通道 |
| 设置变量 | 把维度值或固定值写入某个 Flag | 若已有筛选控件使用该 Flag，相关图会按新值重查 |
| 打开详情 | 浮层里放大一张已有的图 | 浮层内那张图按当前条件查询；这不是编辑器的 Focus 聚焦 |
| 打开仪表盘 | 当前页或新标签打开另一张仪表盘 | 新页面自己的查询；须有目标的查看权限 |
| 打开 URL | 打开 http(s) 地址，可用本次点击的值替换模板 | 否 |
| 刷新面板 | 指定图重新查询 | 是 |
| 重置交互 | 清掉高亮、显隐和当前联动 | 被联动过滤过的图会回到未过滤 |

打开 URL 只允许 http(s)。对外渲染页不执行跳转、也不开详情浮层。嵌入分享不能跳到其它仪表盘。

### 6.4 例子

**点指标卡，邻卡发光并弹出详情**

1. 选中指标卡，交互 Tab 添加规则，触发选「单击」。
2. 添加效果「强调面板」，目标选邻卡，样式选发光。
3. 再添加效果「打开详情」，面板选要放大的那张图，可写标题。
4. 保存仪表盘。查看页单击指标卡内容区（不要点标题上的刷新、全屏）。

**大屏顶栏切换标签页**

1. 画布上先有标签页或轮播容器，以及 [大屏导航](../plugins/screen-nav-menu.md)。
2. 导航的菜单项写成 `key:名称`，例如 `overview:总览, ops:运行`。
3. 在导航的交互 Tab 为 `overview` 添加规则：触发「菜单项」，key 填 `overview`，效果「激活槽位」，容器选那个标签页，页签选总览。
4. `ops` 再加一条规则。导航自己不会改地址，也不会自己切页。

**展厅空闲后回到总览**

在无人值守里设置空闲重置；或给一条空闲触发，效果为激活槽位回到第一页。空闲时间按展厅节奏设置，不要短到观众还在看就被切走。

## 7. 点一个数据点时谁先执行

同一张图上可能同时开了下钻、联动和交互规则。平台按固定顺序处理，避免一次点击做三件互相打架的事：

1. 这张图还能下钻 → 只下钻，不联动，也不执行交互规则。
2. 不能下钻，且这张图是某条联动的主图 → 先按联动过滤从图表。
3. 再执行这张图上匹配的交互规则（例如同时把邻卡高亮）。

面板空白处或装饰上的单击不经过下钻和联动，直接走交互规则。

## 8. 大屏上哪些能点

运行时，纯装饰默认点不中，点击会落到它下面的图上，避免边框、标题装饰挡住图表。下面两类例外：

- 配了交互规则的装饰，或本身会发菜单事件的组件（大屏导航），成为可点热点。
- 大屏标题条上的页签在查看时可以点。编辑器里的装饰预览不可点。

## 9. 配置时常见的错

| 现象 | 原因 | 改法 |
|------|------|------|
| 点了主图，从图表没变 | 主图还能下钻，点击被下钻吃掉 | 关掉下钻，或把联动放到不能再下钻的层级 |
| 下拉改了，图不变 | 作用范围没选这张图，或对应字段没选对 | 在控件上补一行作用范围，字段从数据集选择 |
| 交互 Tab 里加了规则，查看没反应 | 只关了图表编辑器，没保存仪表盘；或规则没有效果 | 保存仪表盘；补上效果 |
| 鼠标划过就跳转或整页重查 | 用了悬停做导航或筛选 | 悬停只留强调 / 显隐；跳转和筛选改成单击或数据点点击 |
| 装饰挡住了下面的图 | 装饰被配成了可点，或误开了整层可点 | 不需要点击的装饰不要加交互规则 |
