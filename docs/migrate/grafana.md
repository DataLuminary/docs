# Grafana 迁入

很多客户已在使用 Grafana。选择 DataLuminary，通常是因为更侧重**数据集治理、自助分析与洞察交付**，而不仅是监控面板。

![Grafana 对照示意](./images/4.png)

## 为何迁 / 为何并存

| Grafana 更擅长 | DataLuminary 更强调 |
|----------------|---------------------|
| 时序监控、告警生态 | 数据集 / 语义模型、自助 BI、AI 洞察 |
| 运维看板 | 经营分析、大屏叙事、权限协作与嵌入业务系统 |

可以短期并存：监控仍留 Grafana，分析与经营看板迁到 DataLuminary。

## 迁入原则

1. **优先迁「分析资产」**：指标口径进数据集与语义模型，而不是把 Grafana 面板 SQL 原样贴进每张图。  
2. **插件相似 ≠ 数据模型相同**：即便面板可扩展，也不建议按 Grafana 方式让图表直连乱查。  
3. **视图迁移（可选、高成本）**：历史上讨论过用微前端把部分 Grafana 插件塞进 DataView 网格；**默认不推荐作为主路径**，需专项评估。  

## 建议路径

1. 盘点现有 Grafana Dashboard：哪些是监控，哪些是经营分析。  
2. 为分析类指标建立 [数据集与语义模型](/product/dataset-modeling)。  
3. 在 DataLuminary 重做图表与仪表盘（或大屏）。  
4. 用 [分享 / 嵌入](/share/) 接到门户；权限走 [统一身份与 ACL](/product/unified-identity)。  
5. 需要对照能力时见 [竞品对比](./compare.md)。

## 我们可协助的范围

- 数据集建模与口径对齐  
- 看板 / 大屏重制与嵌入  
- 私有化与 SSO 落地  

具体工作量按资产规模评估。产品缺口（自动化迁入工具等）见 [未来版本](/product/upcoming)。
